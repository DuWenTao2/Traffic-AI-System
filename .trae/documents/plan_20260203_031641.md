# 视频自动存储功能实现方案

## 一、项目架构分析

### 1. 当前视频处理模块结构
- **VideoReader**：负责视频源读取，支持本地视频、RTSP流和YouTube等在线流
- **VideoProcessorMP**：多进程视频处理器，负责视频帧处理、目标检测和违规识别

### 2. 现有数据流路径
- 视频源 → VideoReader.read() → 视频帧
- 视频帧 → VideoProcessorMP._process_detections() → 目标检测
- 检测结果 → 各个检测器 → 违规识别
- 违规信息 → ViolationManager → 违规记录存储

### 3. 现有存储机制
- **违规记录**：存储到JSON和CSV文件
- **违规截图**：存储到Violation_Proc/violations/snapshots目录
- **事故警报**：存储到JSON和CSV文件

## 二、视频自动存储功能设计

### 1. 功能架构

#### 1.1 新增模块
- **VideoStorageManager**：视频存储管理器，负责视频录制和存储
- **配置选项**：在现有配置文件中添加视频存储相关配置

#### 1.2 集成点
- 在VideoProcessorMP中集成VideoStorageManager
- 在检测开始和结束时触发视频存储
- 与现有违规检测系统无缝集成

### 2. 核心功能实现

#### 2.1 VideoStorageManager类
- **初始化**：配置存储路径、视频格式、编码等参数
- **开始录制**：创建VideoWriter实例，开始写入视频帧
- **停止录制**：停止写入，释放资源，保存视频文件
- **添加帧**：将处理后的视频帧添加到录制中
- **错误处理**：处理存储过程中的异常

#### 2.2 触发逻辑
- **检测开始**：当系统开始检测时触发视频存储
- **检测结束**：当系统停止检测时停止视频存储
- **违规触发**：可选地在检测到违规时保存视频片段

#### 2.3 配置选项
- **存储路径**：视频文件保存目录
- **视频格式**：MP4、AVI等
- **视频编码**：H.264、MJPG等
- **视频质量**：分辨率、帧率等
- **存储模式**：连续存储、事件触发存储等

### 3. 性能优化

#### 3.1 多线程处理
- 使用独立线程进行视频存储，避免影响主处理线程
- 实现帧缓冲机制，平衡处理速度和存储速度

#### 3.2 资源管理
- 合理控制内存使用，避免内存泄漏
- 优化视频编码参数，减少CPU占用

### 4. 代码实现计划

#### 4.1 创建VideoStorageManager类
- 文件：`Processing Models/VideoStorageManager.py`
- 核心功能：视频录制、存储管理、错误处理

#### 4.2 修改VideoProcessorMP类
- 集成VideoStorageManager
- 添加视频存储触发逻辑
- 处理用户输入（如存储控制）

#### 4.3 添加配置选项
- 文件：`config.conf`
- 新增视频存储相关配置

#### 4.4 测试验证
- 功能测试：验证视频存储的完整性和正确性
- 性能测试：验证对系统性能的影响
- 兼容性测试：验证与现有功能的兼容性

## 三、预期效果

1. **完整记录**：准确记录从检测开始到结束的全过程视频
2. **系统兼容**：与现有功能模块无缝集成，无负面影响
3. **性能稳定**：CPU占用增加不超过5%，内存使用合理
4. **可靠存储**：完善的错误处理，确保存储过程的可靠性
5. **灵活配置**：支持存储路径、视频格式等参数的配置

## 四、技术要点

1. **视频编码选择**：使用H.264编码，平衡压缩率和CPU占用
2. **多线程设计**：独立存储线程，避免影响主处理线程
3. **帧缓冲机制**：处理视频帧的异步添加
4. **错误恢复**：存储过程中断后的恢复机制
5. **文件管理**：自动命名和管理视频文件，避免冲突
