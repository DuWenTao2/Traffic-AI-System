# 司机违规行为检测功能替换方案

## 1. 方案概述

基于现有系统架构，将头盔检测功能完整替换为司机违规行为检测功能。新功能将使用指定的模型权重文件，识别驾驶员使用手机、未系安全带等违规行为，同时保持与现有系统的接口兼容性。

## 2. 核心实现步骤

### 2.1 创建新的驾驶员违规行为检测模块

**文件路径**：`Models/Driver_Violation_Detection/driver_violation_detector.py`

**功能实现**：
- 继承原有头盔检测模块的架构设计
- 使用指定权重文件 `\weights\Driver_Violation_Detection\best.pt`
- 实现三类违规行为检测：'mobile'（使用手机）、'person'（人员）、'seatbelt'（安全带）
- 保持与现有系统的接口一致

### 2.2 更新 VideoProcessorMP.py 集成代码

**修改内容**：
- 将头盔检测模块的导入路径更新为驾驶员违规行为检测模块
- 将所有涉及 "helmet_detection" 的代码、注释及配置项更新为 "driver_violation_detection"
- 保持检测流程的集成方式不变

### 2.3 更新配置文件

**文件路径**：`所有检测功能开关控制配置文件.json`

**修改内容**：
- 将 "helmet_detection" 配置项更新为 "driver_violation_detection"
- 确保默认值设置合理

### 2.4 更新用户界面文本

**修改内容**：
- 更新所有涉及 "安全帽检测" 的用户界面文本为 "驾驶员违规行为检测"
- 更新相关按键提示和状态信息

## 3. 技术实现细节

### 3.1 检测流程设计

1. **车辆检测**：使用现有 YOLOv8 模型识别车辆目标
2. **区域提取**：对识别到的车辆目标，提取包含驾驶舱的 ROI
3. **违规行为检测**：将 ROI 输入到驾驶员违规行为检测模型
4. **结果处理**：识别三类违规行为的存在状态及置信度
5. **违规记录**：使用统一的违规管理系统记录违规行为

### 3.2 模型配置

- **模型路径**：`\weights\Driver_Violation_Detection\best.pt`
- **类别映射**：
  - 0: 'mobile'（使用手机）
  - 1: 'person'（人员）
  - 2: 'seatbelt'（安全带）

### 3.3 接口兼容性

- 保持与原有头盔检测模块相同的类名和方法签名
- 确保 `process_frame` 方法的输入输出格式一致
- 保持 `has_detection` 状态标志的使用方式
- 确保违规记录格式与现有系统兼容

### 3.4 性能优化

- 采用与原有模块相同的推理节流策略
- 保持相同的目标跟踪机制
- 确保处理速度与原有模块相当

## 4. 实现计划

1. **创建驾驶员违规行为检测模块**：实现核心检测逻辑
2. **更新 VideoProcessorMP.py**：集成新模块
3. **更新配置文件**：修改功能开关配置
4. **测试验证**：确保功能正常运行且与现有系统兼容
5. **性能测试**：验证实时性和稳定性

## 5. 预期效果

- 系统能够准确识别驾驶员使用手机、未系安全带等违规行为
- 检测结果清晰标识三类违规行为的存在状态及置信度
- 与现有系统架构完全兼容，不影响其他功能模块
- 保持系统整体性能和响应速度

## 6. 技术风险评估

- **模型兼容性**：确保指定模型与现有 YOLO 框架版本兼容
- **性能影响**：新模型可能对系统性能产生一定影响，需进行测试验证
- **集成风险**：确保接口变更不影响其他系统模块

## 7. 解决方案

- 采用模块化设计，确保替换过程中的系统稳定性
- 保持与现有接口的兼容性，最小化代码变更
- 进行充分的测试验证，确保功能正常运行
- 提供详细的实现文档，便于后续维护和扩展
