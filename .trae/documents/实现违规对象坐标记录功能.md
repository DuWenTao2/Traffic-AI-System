# 实现违规对象坐标记录功能

## 问题分析
当前系统在生成违规记录时，虽然接收了边界框(bbox)坐标参数，但没有将这些坐标信息保存到违规记录中。需要修改违规记录生成与存储的相关代码，确保坐标数据的准确采集与关联存储。

## 解决方案

### 1. 修改核心违规记录生成方法
- 在 `Violation_Proc/violation_manager.py` 文件的 `_record_violation` 方法中，添加坐标信息处理逻辑
- 在创建 `violation_record` 时，添加 `bounding_box` 字段，存储标准化的坐标数据
- 实现坐标数据的标准化处理，确保格式统一

### 2. 封装通用坐标处理函数
- 在 `violation_manager.py` 中添加 `_process_bounding_box` 方法，用于标准化处理不同类型违规对象的坐标
- 该函数将处理坐标的验证、标准化和默认值设置

### 3. 确保坐标数据的完整性
- 修改 `_update_json_log` 方法，确保坐标数据被正确保存到 JSON 文件中
- 确保在生成手动审核记录时，坐标数据也被包含在内

### 4. 坐标数据格式
使用统一的坐标格式：
```json
"bounding_box": {
  "x": 100,      // 左上角X坐标
  "y": 200,      // 左上角Y坐标
  "width": 50,    // 宽度
  "height": 30    // 高度
}
```

### 5. 代码修改点
1. `Violation_Proc/violation_manager.py`
   - 添加 `_process_bounding_box` 方法
   - 修改 `_record_violation` 方法，添加坐标处理
   - 确保坐标数据在整个记录流程中被正确传递和保存

### 6. 测试计划
- 验证不同类型违规对象的坐标记录
- 验证坐标数据的格式统一性
- 验证系统现有功能是否正常运行
- 验证未获取坐标时的默认值处理

## 预期结果
修改后，所有违规记录将包含准确的坐标信息，便于后续的分析和处理。同时，修改将保持系统的稳定性和现有功能的完整性。
